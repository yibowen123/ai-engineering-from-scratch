# AlphaZero, MuZero, and GRPO — A Detailed Explainer

> Three landmark algorithms, one idea: **self-play → search/sampling improves the raw policy → train the network to match the improvement.** AlphaZero needs the rules. MuZero learns them. GRPO throws out the tree entirely and applies the same improvement principle to language-model reasoning. This note explains each in depth and shows exactly how they relate.

**Companion to:** `docs/en.md` (the lesson) and `code/main.py` (GRPO in miniature).
**Prerequisites assumed:** DQN (L05), PPO (L08), RLHF (L09), MARL (L10) — all in this phase.

---

## 0. The one loop they all share

Every algorithm here is an instance of **generalized policy iteration** with a twist: the "policy improvement" step is done by an *external process that is stronger than the raw network*, and the network is then trained (supervised) to imitate that stronger process.

```
while not converged:
    trajectory   = act(current_policy, improver)   # self-play game, or sampled completions
    better_policy = improver(trajectory)            # MCTS visit counts, or group-relative reweighting
    network.update(toward better_policy, and toward observed value/reward)
```

- **AlphaZero / MuZero:** the `improver` is **MCTS**. Search looks ahead, so its move distribution is better than the network's raw prior. The network is trained to predict (a) what search decided and (b) who won.
- **GRPO:** the `improver` is **group-relative reweighting**. Sampling G completions and ranking them by a verifier tells you which completions were better than average. The network is trained to make the better-than-average ones more likely.

Hold this frame. Everything below is a specialization of it.

## 1. AlphaZero (2017)

**Setting:** two-player, zero-sum, perfect-information games with **known rules** (chess, shogi, Go). Zero human data, zero handcrafted heuristics.

### 1.1 The network — one tower, two heads

A single deep residual network `f_θ(s) → (p, v)`:

- `p` — a **policy prior**: a probability distribution over legal moves in position `s`.
- `v ∈ [-1, +1]` — a **value**: the expected game outcome from `s` under current self-play (≈ "am I winning?").

This is literally the actor-critic split from Phase 09 L07 — a policy head and a value head sharing a trunk — but trained very differently (see §1.4).

### 1.2 The improver — MCTS with PUCT

At every move the agent builds a search tree rooted at the current position. It runs hundreds–thousands of **simulations**, each of which:

1. **Select.** Descend the tree by picking, at each node, the action maximizing the **PUCT** score:

   $$a^\* = \arg\max_a \left[\, Q(s,a) \;+\; c_{puct}\, p(a\mid s)\, \frac{\sqrt{\sum_b N(s,b)}}{1 + N(s,a)} \,\right]$$

   - `Q(s,a)` — mean value backed up through this edge so far (**exploitation**).
   - `p(a|s)` — the **network prior**: focuses search on moves the net thinks are good.
   - `√ΣN / (1+N(s,a))` — an **exploration bonus** that decays as edge `a` is visited more. `c_puct` trades off the two.

2. **Expand.** On reaching a leaf, call `f_θ` once to get `(p, v)` for that new node. The game's *known rules* give the legal moves and the next state.

3. **Backup.** Propagate `v` up the path, updating each `Q(s,a)` and incrementing visit counts `N(s,a)`.

After the simulation budget is spent, the tree has concentrated visits on strong moves. The **visit-count distribution** at the root,

$$\pi(a\mid s) = \frac{N(s,a)^{1/\tau}}{\sum_b N(s,b)^{1/\tau}},$$

is the improved policy. Crucially, `π` (after lookahead) is *stronger than the raw prior* `p` (no lookahead) — this gap is the engine of learning.

### 1.3 Self-play

The agent plays full games against itself, selecting moves by sampling from `π` (with temperature `τ` high early for exploration, →0 later). Each move stores the tuple `(s, π_s)`. When the game ends with outcome `z ∈ {+1, 0, -1}`, that `z` (from the mover's perspective) is attached to every stored position. No human games, no opening book — the data distribution is entirely generated by the current network searching against itself.

### 1.4 The loss — imitate the search, predict the winner

$$L(\theta) = \underbrace{(v_\theta(s) - z)^2}_{\text{value: regress to outcome}} \;\underbrace{-\; \pi_s \cdot \log p_\theta(s)}_{\text{policy: cross-entropy to MCTS visits}} \;+\; \underbrace{c\,\lVert\theta\rVert^2}_{\text{weight decay}}$$

Read carefully what this does:

- The **value head** is trained by regression toward the eventual game result `z` — a Monte Carlo (not bootstrapped) target.
- The **policy head** is trained by **cross-entropy toward the MCTS visit distribution `π`** — *not* toward the action actually played, and *not* by policy gradient. The network is doing **supervised distillation of its own search.**

This is the key conceptual move of AlphaZero: **search produces a better policy than the network; the network is trained to catch up to its own search; the now-stronger network makes the next search even better.** A virtuous cycle. It mastered chess, shogi, and Go from random initialization, each after tens of millions of self-play games.

### 1.5 Why it needs the rules

MCTS's Expand step asks "what states follow from this one?" — that requires a **perfect simulator**. For board games the rules *are* that simulator. The moment the rules are unknown or the dynamics must be learned, AlphaZero can't run. That is exactly the restriction MuZero removes.

## 2. MuZero (2019)

**Setting:** same self-play + MCTS + distillation loop, but **the rules are no longer given.** One algorithm now spans Go, chess, shogi *and* Atari (where no one hands you a simulator).

### 2.1 The insight — you don't need the real model, only a model good enough to plan

MuZero never reconstructs pixels or board states. It learns a **latent dynamics model** whose *only* obligation is to predict the quantities MCTS and training actually consume: **policy, value, and reward.** If a latent transition predicts those correctly, it doesn't matter that it bears no resemblance to the true game state.

### 2.2 Three learned functions

- **Representation** `h`: `h(o_1, …, o_t) → s^0`. Encode the observation history into an initial **latent state** `s^0`.
- **Dynamics** `g`: `g(s^k, a^{k+1}) → (s^{k+1}, r^{k+1})`. Given a latent state and an action, predict the **next latent state** and the **immediate reward**. This is the learned stand-in for the game's transition function.
- **Prediction** `f`: `f(s^k) → (p^k, v^k)`. From a latent state, predict the **policy prior and value** — same role as AlphaZero's `f_θ`.

### 2.3 Search in latent space

MCTS runs exactly as in AlphaZero, with one substitution: the Expand step calls the **learned `g`** instead of the real rules to generate children, and `f` to evaluate them. The tree is now a tree of *imagined latent states*. PUCT selection, backup, and the visit-count target `π` are unchanged.

### 2.4 Training — unroll and match observed signals

For each real trajectory, MuZero **unrolls** the model `K` steps from a sampled start, feeding the actions that were actually taken, and trains every head against grounded targets:

$$L(\theta) = \sum_{k=0}^{K} \Big[ \underbrace{(r^k_\theta - u^k)^2}_{\text{reward}} + \underbrace{(v^k_\theta - z^k)^2}_{\text{value, via n-step bootstrap}} + \underbrace{\big(-\,\pi^k \cdot \log p^k_\theta\big)}_{\text{policy, to MCTS visits}} \Big]$$

where `u^k` are observed rewards and `z^k` are n-step-bootstrapped value targets. There is **no loss that forces `s^k` to match any true state** — the latent space is free to organize itself however best predicts reward/value/policy. That freedom is why MuZero works without a simulator.

### 2.5 Relationship to AlphaZero

| | AlphaZero | MuZero |
|---|---|---|
| Rules / simulator | **given** | **learned** (`g`) |
| Search space | real game states | **latent** states |
| Heads | policy, value | policy, value, **reward** |
| Value target | final outcome `z` | n-step bootstrap |
| Domains | perfect-info board games | board games **+ Atari** |
| Core loop | self-play + MCTS + distill | **identical** |

**Lineage worth knowing:** *Stochastic MuZero* (2022) adds chance nodes for stochastic games (e.g. backgammon); *Gumbel MuZero* (2022) makes search reliable at tiny simulation budgets; *Sampled MuZero* handles large/continuous action spaces. All keep the same skeleton.

## 3. GRPO (2024) — the AlphaZero recipe, minus the tree, for LLM reasoning

**Setting:** teach a language model to reason (math, code, logic) where correctness is **verifiable** — a checker returns 1 if the final answer is right (unit tests pass, number matches) else 0. Introduced in **DeepSeekMath** (Feb 2024) and scaled in **DeepSeek-R1** (Jan 2025).

### 3.1 Reframing a reasoning problem as a game

| Game concept | LLM-reasoning instantiation |
|---|---|
| Environment | a prompt (a problem to solve) |
| State | prompt + tokens generated so far |
| Action | the next token |
| Episode / rollout | one full completion |
| "Win" (reward) | verifier returns 1 (correct) / 0 (wrong) |
| Self-play | sampling multiple completions from the current policy |

### 3.2 The problem GRPO solves: get rid of the critic

PPO-RLHF (Phase 09 L09) needs a **value network `V_φ`** to compute advantages `A = r - V_φ(s)`. For an LLM that critic is *another model the size of the policy* — doubling memory, and hard to train because reasoning reward is **sparse** (one scalar at the very end of a long completion).

GRPO's move: **replace the learned baseline with a group-relative one.** For a prompt `q`, sample a **group** of `G` completions `{o_1, …, o_G}` from the current policy, score each with the verifier, and define the advantage of each completion purely by how it compares to its own group:

$$A_i = \frac{r_i - \operatorname{mean}(r_1, \dots, r_G)}{\operatorname{std}(r_1, \dots, r_G) + \varepsilon}$$

The group mean **is** the baseline; the group std normalizes it. No critic, no reward model network — just the verifier and some arithmetic.

### 3.3 The loss

$$L_{GRPO}(\theta) = -\,\mathbb{E}_{q,\{o_i\}}\!\left[\frac{1}{G}\sum_{i=1}^{G} A_i \,\log \pi_\theta(o_i \mid q)\right] \;+\; \beta\, \mathrm{KL}\!\big(\pi_\theta \,\Vert\, \pi_{ref}\big)$$

- **First term** — REINFORCE weighted by the group-relative advantage: push up the log-prob of better-than-average completions, push down worse-than-average ones. (Production GRPO wraps this in a PPO-style clipped ratio with multiple inner epochs; the group baseline is the essential part.)
- **KL term** — pull the policy toward a frozen **reference** (usually the SFT model), preventing it from drifting into degenerate or off-distribution text. Exactly the RLHF anchor from L09.

### 3.4 Why this is AlphaZero-shaped

Line up the unifying loop from §0:

- **Self-play / acting** → sample `G` completions from the current policy.
- **Improver** → the verifier + group ranking tells you which completions beat the group average. That ranking is a *better policy signal than the raw network* — the same role MCTS visit counts play in AlphaZero.
- **Network update** → increase probability of the above-average completions (toward the "improved" distribution), regress nothing (no value net), stay near reference.

GRPO is the search-free degenerate case: instead of a *lookahead tree* producing a better move distribution, you use *parallel sampling + a verifier* producing a better completion distribution. Same principle — **let a stronger external process label what "good" looks like, then imitate it.**

### 3.5 Grounding it in `code/main.py`

The lesson's `grpo_step` is this loss stripped to a one-token bandit — read it as the LLM's final-layer softmax over answer tokens:

```python
samples = [sample(probs, rng) for _ in range(G)]      # G completions from policy
rewards = [verify(p_idx, s) for s in samples]          # verifier: 1 correct / 0 wrong
mean_r = sum(rewards) / G
std_r  = sqrt(var_r) + 1e-8
advs   = [(r - mean_r) / std_r for r in rewards]       # <-- group-relative advantage

for a, A in zip(samples, advs):                        # REINFORCE weighted by A_i
    for i in range(N_ANSWERS):
        grad_logpi = (1.0 if i == a else 0.0) - probs[i]   # d log pi / d logit_i
        theta[p_idx][i] += (lr / G) * A * grad_logpi

for i in range(N_ANSWERS):                             # KL pull toward reference
    theta[p_idx][i] -= beta * (probs[i] - probs_ref[i])
```

`grad_logpi = onehot(a) - probs` is the softmax score function you've now seen in every policy-gradient port this phase. The *only* new idea over L09's RLHF is **where the baseline comes from**: there it was a running/critic baseline; here it's the **group mean/std**, computed fresh per prompt. That single change is the DeepSeek contribution.

### 3.6 Why GRPO beats PPO for reasoning (DeepSeekMath, §4)

1. **No value network** → roughly halves training memory and removes a hard-to-fit model.
2. **Group baseline fits sparse terminal reward naturally** → reasoning gives one reward at the end; a per-prompt group mean is a clean, low-bias baseline for exactly that structure.
3. **Per-prompt normalization makes advantages comparable across problems** of wildly different difficulty — a single global critic (PPO) cannot calibrate an easy problem against a hard one; dividing by each group's own std does.

### 3.7 The R1 recipe (what GRPO enabled)

- **R1-Zero:** GRPO straight on the base model, **no SFT**, with rule-based **accuracy** + **format** rewards (`<think>…</think>`). Response length self-organizes from ~100 → ~10,000 tokens; the model *learns to reason from scratch*. Downside: messy, language-mixed chains of thought.
- **R1:** a four-stage pipeline fixing readability — (1) cold-start long-CoT SFT, (2) reasoning GRPO + language-consistency reward, (3) rejection-sample ~600K good traces + 200K general SFT, (4) full-spectrum GRPO over reasoning *and* alignment. Matches o1 on AIME/MATH-500 at open weights.
- **Distillation:** SFT'ing small models (1.5B–70B) on R1's traces beats running RL at the small scale — a strong RL teacher distills better than students can self-improve.

## 4. Side-by-side

| Axis | AlphaZero | MuZero | GRPO |
|---|---|---|---|
| Year / origin | 2017, DeepMind | 2019, DeepMind | 2024, DeepSeek |
| Domain | known-rule board games | board games + Atari | LLM reasoning (verifiable) |
| Needs rules/simulator? | **yes** | **no** (learns `g`) | n/a (sampling, no model) |
| Improver | MCTS (real states) | MCTS (latent states) | group sampling + verifier |
| Policy target | MCTS visit counts `π` | MCTS visit counts `π` | group-relative advantage `A_i` |
| Value / critic | value head → outcome `z` | value head → n-step | **none** (group baseline) |
| Reward | terminal win/loss | learned per-step reward | verifier (terminal, rule-based) |
| Exploration | PUCT + temperature | PUCT + temperature | sampling temperature over `G` |
| Anchor | — | — | KL to reference policy |
| Update style | supervised distillation | supervised distillation | policy gradient (clipped) |

**The through-line:** *acquire a better-than-network policy signal from an external process, then train the network to match it.* AlphaZero and MuZero get that signal from **lookahead search**; GRPO gets it from **parallel sampling against a verifier**. Search-based methods still rule long-horizon perfect-information games; GRPO rules verifiable LLM reasoning today — and the open question (hinted by process-reward models) is whether tree search comes *back* to LLMs, closing the loop to a true MuZero-for-reasoning.

## 5. Pitfalls carried over from the lesson

- **Verifier gaming (GRPO).** A wrong/exploitable checker gets exploited — robust verifiers (many test cases, formal checks) matter. Inherits RLHF's reward-hacking risk.
- **Group size (GRPO).** Baseline variance ~`1/√G`; below `G=4` the signal is noisy. Standard `G = 8–64`.
- **Length bias (GRPO).** Longer completions have different total log-prob; normalize by token count or use sequence-level log-prob.
- **Self-play cycles (AlphaZero).** General-sum games can fall into dominance loops; mitigate with league/opponent diversity (L10).
- **Search–policy mismatch (AlphaZero/MuZero).** If the net is too small to represent the search distribution, distillation stalls.
- **Compute floor (AlphaZero/MuZero).** Hundreds of GPU-hours per ablation; use miniature demos (Connect Four) to learn.
